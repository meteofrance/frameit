# Post-run Best-track Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run an explicitly requested, experimental `best_track` analysis against a completed FrameIt extraction without rerunning it or modifying its records and products.

**Architecture:** Add a versioned parent attempt contract, then admit a read-only diagnostic plan under the parent lock. Bind just the selected fields from one source, stream deterministic native-grid reductions under a serial resource scope, and publish a separate child attempt with canonical SI values, quality flags, and an RSMC La Réunion CSV.

**Tech Stack:** Python 3.13 `frameit_env`, existing FrameIt YAML/report/locking code, xarray and its installed backends, NumPy, pyproj, NetCDF4, and standard-library CSV.

**Spec:** User-supplied `FrameIt_Run_Diag_Architecture.md`, v1.1, 2026-11-25 (SHA-256 `22ee638e839ae8c299888cc43871e1ebb28a73fe5cdb8789a94f2a017d699bd5`). The public and scientific requirements below refer to sections of that handoff.

## Review focus

- An overwrite with no new centres must not hand an old trajectory to the new attempt: Task 2 tests previous-attempt replay.
- A relocated crop must work without a raw glob, a parent catalogue cache, or a reconstruction of deleted authored settings: Tasks 2–4 test relocation, missing raw inputs, and strict authored projection separately.
- A field with 600-second bounds, but no evidence of a compatible wind averaging operator, must not populate a strict column: Tasks 4–6 test a rotating component-mean example and both availability policies.
- A tile edge, missing wedge, or disconnected outer strong-wind area must not yield a spurious zero radius or an agency-eligible core maximum: Tasks 5–6 test coverage/rim invariance, explicit censoring, and CSV blanks.
- An apparently successful write followed by failing scope cleanup must not commit, while a lock failure after commit must not imply rollback: Task 3 injects both failures; Task 7 repeats scope cleanup coverage for Zarr.
